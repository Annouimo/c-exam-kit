# 开发与发布

## 唯一维护来源

修改 `catalog/catalog.json`、`templates/` 和 `src/`，运行 `python3 tools/build.py`。生成的 `dist/c_scaffold_v版本号.c` 一起提交；完整文档输出到忽略的 `release/`，不提交。`--check` 校验源码和已有文档是否过期，并始终校验文档配置与占位符。工程不依赖旧版本快照、临时目录、个人绝对路径或早期脚本。

## 新增组件

1. 在 `templates/pieces/` 添加C代码。函数、全局状态、结构体可作为多个独立piece，共用内容只保留一份。
2. 在JSON的 `pieces` 添加稳定 `id`、`source`、`details` 和 `hint`；可用 `requires` 声明其他piece依赖。需要long long数组变体时增加 `wide_source` 和 `wide_details`。
3. 在 `components` 添加名称、短名称、分类编号、简短目录说明、前提、帮助、piece列表和容量 `caps`。依赖会递归展开，循环和未知依赖会报错。
4. 分类内的实际数组顺序就是菜单顺序，显示序号自动生成。内部关联使用稳定ID，不使用菜单编号。
5. 重新构建并运行测试。仅增加普通组件不需要修改核心流程。

## 骨架和main片段

`io` 和 `fragments` 指向独立C模板。骨架支持 `@BODY@`、`@LOOP@`、`@INPUT@`、`@OUTPUT@` 放置位置；main片段的 `phase` 为0读入、1处理、2输出。`VALUE`、`VALUE_SCAN`、`VALUE_PRINT` 根据选中的int/long long展开，`SEPARATOR_LITERAL` 展开为安全的C字符串字面量。

容量通过 `capacities` 定义字段、宏、标签、默认值和范围；`extra` 表示终止符等额外空间。组件及片段在 `caps` 声明需求，只有选中相关内容才询问、生成对应容量。`SEPARATOR` 表示需要分隔符配置。`default_separator` 是片段的首次建议值；同时选择多个输出片段时，共用一次分隔符配置。

JSON只存元数据和路径，不嵌入长段转义代码。C代码保持普通格式，方便编辑器高亮与检查。

## 文档：文字手工维护，重复内容自动生成

| 文件 | 修改内容 |
| --- | --- |
| `docs/templates/exam_handbook.md` | 前言、使用说明、例子、章节顺序和自动内容的位置 |
| `catalog/handbook/references.json` | 标准库表格、简短函数索引；每行按列填写 |
| `catalog/handbook/profile.json` | 元数据、输出路径、各主题收录的组件稳定ID |
| `catalog/handbook/pdf.json` | PDF字体、颜色、字号、页边距、表格列宽、页眉页脚 |
| `docs/templates/scaffold_manual.md` | 详细手册的说明文字和自动内容位置 |
| `docs/templates/scaffold_appendix.md` | 独立目录的说明文字和自动内容位置 |

模板中的 `{{ tables.名称 }}`、`{{ indexes.名称 }}`、`{{ scaffold.主题 }}` 分别展开为表格、紧凑函数索引、组件列表。组件名称和摘要仍以 `catalog/catalog.json` 为唯一来源。每个函数组件必须恰好归属一个手册主题；增加组件后同步填写主题归属。菜单编号自动关联，不在模板里硬写。未知占位符、遗漏或重复组件会阻止构建，避免静默丢失内容。

说明段落可以直接改写，保留所需占位符即可。HTML注释仅供编辑者阅读，不进入成品。不要编辑 `release/` 中的展开结果，重新构建会覆盖它们。

```sh
python3 tools/build.py --docs-only
python3 tools/build_pdf.py --preview
```

这会生成带版本号的考试手册Markdown、独立目录、全量函数手册与PDF。PDF直接读取同一模板和配置，无需先保存完整Markdown。正式构建省略 `--preview`。仓库只保留维护输入，完整文档随Release分发；分支CI的 `source-and-documents` artifact可下载检查。

程序仍可通过 `--manual` 导出内置全量手册，无需外部文件。本轮只抽离文档内容与样式；运行时的界面文字及C语言装配逻辑尚未完全配置化。

## 版本与Release

脚手架版本由 `catalog/catalog.json` 的 `version` 管理，自动带入程序、生成代码、详细手册和工程包。手册版本独立维护在 `catalog/catalog.json` 的 `handbook_version`；README、更新记录与Release说明也需同步。

首次发布为脚手架v0.4.0、手册v1.4。推送main触发构建；Release只有在所有平台检查成功后才创建。发布脚本使用Actions提供的短期令牌，源码不保存个人访问令牌。已有同名Release时保留现有产物，修订需提升版本号。

Windows编译需链接user32；生成的数学题代码可能需链接math库。Windows/macOS桌面剪贴板交互应由维护者在真实环境试用，CI覆盖编译及macOS复制管道模拟。

## v0.5.0 编码与分发

最终单文件名由版本生成，例如 `c_scaffold_v0.5.0.c`。构建脚本将C字符串中的非ASCII字符变成固定三位八进制UTF-8字节转义，注释变成ASCII表示；工程输入仍保留可读中文。源码开头的英文编译运行提示不受UTF-8/GBK误判影响。构建会移除旧的已生成单文件，避免同时存在多个版本。

`src/text_io.c`统一封装显示输出和行输入：Windows按输入/输出句柄分别检测真实控制台，用W接口与UTF-16交互；重定向默认UTF-8，显式GBK兼容选项仅作用于标准流。普通文件流和剪贴板始终保持原有编码。跨调用分开的UTF-8字节暂存后再转换，防止逐字节输出破坏中文。

PDF构建独立于普通源码构建，由 `tools/build_pdf.py` 使用本地Pandoc、ReportLab和FontTools排版并嵌入子集中文字体；字体使用Noto CJK，不加载外部网页或字体。Release仅发布源码和文档，跨平台编译仅用于验证。
